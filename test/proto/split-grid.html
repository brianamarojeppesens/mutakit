R1 prototype — can CSS Grid express the split clamping cascade?

Drag either separator hard against its limits. In neighbor and distribute modes, JavaScript writes one unclamped pixel value per pointer move and does no arithmetic beyond start + delta — every bound you observe is applied by clamp() / min() inside grid-template-columns. In push mode JS computes the cascade itself; watch the JS ops/move counter change.

Known limit — distribute. While gutter 0 is dragged, pane 1 becomes minmax(min, 1fr) so the remainder spreads proportionally. That gives the track a floor but no ceiling: fr maxima are uncapped by construction, so pane 1 can sail past max1 and the verdict below will correctly say so. The size is committed and re-clamped on release. Dragging gutter 1 keeps pane 1 explicit — with --t1 pinned at 1fr, --w1 is inert and that separator cannot move at all.
